# Leagues and tournaments, Teams and placement (SCR-S-08 to SCR-S-13, SCR-S-16 to SCR-S-19)

Staff screens for competition setup, fixture generation, readiness, results, disputes and
discipline, standings and brackets, team entries, rosters, placement and youth groups
(`docs/package-a/screen-and-journey-inventory.md` section 5). They talk only to the API through
`@sportspark/api-client`; the API's fake providers stand behind it (§5.2).

Status legend (§6.7): **Verified** = implemented and asserted by a test here (jsdom with a fake
API; not staff acceptance on real devices, §6.3). **Proposed** = engineering proposal awaiting
operator approval, including how an API gap is presented. **Pending decision** = needs an operator
answer; the screen names the decision and its owner instead of inventing the value.

## API gaps found while building these screens

- No list of submitted result revisions across a season, of disputes, of disciplinary decisions,
  of appeals, of fixture specifications of a division or of solver runs; each is read by id only.
- No list-level readiness (one `GET /fixtures/{id}/readiness` per row) and no team names on
  `Fixture`, `TeamEntry` or `BracketNode` (one `GET /teams/{id}` per team).
- `PlacementRequest`, `Suspension` and `Enrollment` carry no display name; showing one means
  reading the whole `Person` (including the date of birth) for a name (§4.14 minimization).
- No season copy command (SCR-S-08), no youth group membership or progression recommendation
  commands (SCR-S-19), no person search.
- No `availableActions` on competition, placement or capacity records.
