# Reports and Administration (SCR-S-43 to SCR-S-48)

Staff screens for operating reports, utilization, economics, demand and retention, stored runs
and exports, accounts and roles, integrations and configuration, and migration imports and
reconciliation (`docs/package-a/screen-and-journey-inventory.md` section 5). They talk only to the
API through `@sportspark/api-client`; the API's fake providers stand behind it (§5.2).

Status legend (§6.7): **Verified** = implemented and asserted by a test here (jsdom with a fake
API; not staff acceptance on real workstations, §6.3). **Proposed** = engineering proposal awaiting
operator approval, including how an API gap is presented. **Pending decision** = needs an operator
answer; the screen names the decision and its owner instead of inventing the value.

Routes are registered once in `src/App.tsx` through `insightAdminRoutes()` (`routes.tsx`), before
the area placeholders. The Reports area is marked `ownRoutes`; the Administration area keeps its
page and lists these screens through `links` in `src/navigation/areas.ts` (the support cases screen
SCR-S-49 and access hardware SCR-S-56 belong to other groups). Each Administration screen built
here carries the `AdminNav` sub-navigation ("Administration pages"). Shared pieces here:
`ReportView.tsx` and `ReportPanel.tsx` (one report envelope with every metric definition, how it
was read and the settings it used), `ReportParameters.tsx`, `feedback.tsx` (SPK-UX-008 states,
permission restriction with the API's message, API gaps, pending decisions), `fields.tsx` (labelled
fields), `labels.ts` (machine-state vocabulary and decision owners), `format.ts`, `facilities.ts`
(the facility directory `GET /v1/facilities` limited to the staff scope, with IANA zones and local
dates), `audit.tsx` (audit record list and per-record audit trail, read only on an explicit
action), `names.ts` (display names through `GET /v1/person-names`, 100 ids per read),
`PersonSearch.tsx` (find an adult person by name through `GET /v1/people`), `permission.tsx`
(`ActionGate`: a command offered only when `GET /v1/me/permissions` lists its action),
`download.ts` (single-use export download), `staging.ts`,
`migration.tsx`, `insight-admin.css`. Tests: `src/screens/reports/__tests__`,
`src/screens/admin/__tests__`, `__tests__/helpers.test.ts`; fixtures in `__tests__/fixtures.ts`.

## Gaps still open (presented as "Not available yet" or pending, **Proposed** handling)

- Changing organization or facility settings and integration configuration: no API command
  (core.manage_organization_settings, core.manage_facility, core.manage_integration stay
  Proposed, DEC-013); facility addresses wait on DEC-001. Settings are read-only here.
- An earlier export cannot be downloaded again from the list: its single-use token is returned
  only when it is made and the typed client keeps the download a header (`X-Export-Token`), so a
  new export of the same run is offered instead.
- Per-record `availableActions` for import batches, exceptions and reconciliation reports are not
  planned (only workforce assignments and the team workspace carry them). The role view from
  `GET /v1/me/permissions` decides which migration step is offered; whether a given exception
  queue or sign-off area is the viewer's is still decided by the API per record, and its
  ACCESS_DENIED is shown.
- Uncomputed metrics stay "Not available" with the API's reason; metric definitions are not
  editable (not planned).
