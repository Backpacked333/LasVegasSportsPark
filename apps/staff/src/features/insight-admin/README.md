# Reports and Administration (SCR-S-43 to SCR-S-48)

Staff screens for operating reports, utilization, economics, demand and retention, stored runs
and exports, accounts and roles, integrations and configuration, and migration imports and
reconciliation (`docs/package-a/screen-and-journey-inventory.md` section 5). They talk only to the
API through `@sportspark/api-client`; the API's fake providers stand behind it (§5.2).

Status legend (§6.7): **Verified** = implemented and asserted by a test here (jsdom with a fake
API; not staff acceptance on real workstations, §6.3). **Proposed** = engineering proposal awaiting
operator approval, including how an API gap is presented. **Pending decision** = needs an operator
answer; the screen names the decision and its owner instead of inventing the value.

## API gaps (presented as "Not available yet", **Proposed** handling)

- No list of a requester's exports: only exports made on the open page are shown; leaving the page
  means making a new export.
- No list or single read of staff memberships or staff accounts, and no read of the audit of
  privileged actions: a membership can be changed only right after it is assigned on the page, and
  a stale revision cannot be reloaded there.
- No integration register (§5.1 fields, evidence levels) and no organization or facility settings
  command: provider gates are shown as pending and settings are read-only (names, time zones and
  local dates come from the Today feed).
- No list of a batch's reconciliation reports: a report is shown when generated and by its id.
- Import batches carry no `availableActions`, so the next step follows the batch state machine and
  the API's ACCESS_DENIED is shown when the viewer may not take it.
- The OpenAPI document publishes some fields with the wrong nullability (`ImportOutcomeCounts`
  and `ImportRowOutcome` as nullable everywhere, `decidedBy` as never null); the screens tolerate
  both.
