# Architecture overview

Status legend: **Verified** = implemented and tested in this repository today (file cited). **Proposed** = engineering proposal from the specification or from this document, awaiting operator approval. **Pending decision** = needs an operator answer; the owner is named from specification §6.6. "No answer yet" never becomes "not applicable" (§6.6). Code that exists but that no test asserts is described as "implemented, not asserted by a test" and is never marked **Verified**.

Last derived from specification v2.0 (2026-10-22). Source: `docs/spec/master-specification.md` (repository copy supplied 2026-10-23). Repository state inspected 2026-10-24: `apps/api/src/modules/index.ts` lists 14 domain modules, of which eight are implemented (identity, catalog, scheduling, competition, facilities, communications, enrollment, workforce) and six are scaffolds; migrations `0001`, `0100`, `0200`, `0300`, `0400`, `0450`, `0500`, `0700`, `0900` and `1000` are present in `packages/db/migrations/`.

This document describes the backend shape (§4.1), the kernel's request path and background work (§4.8 to §4.12, §4.14), how domain modules plug their authority into the kernel, and the module map (§4.2). Entities and lifecycles are in `docs/architecture/domain-model.md`; commands, errors and events are in `docs/architecture/api-and-events.md`. In the tables below, `kernel/` means `apps/api/src/kernel/` and `modules/` means `apps/api/src/modules/`.

## 5. Data conventions (spec §4.3, §4.4, §4.7)

The rules are stated in `CLAUDE.md`: organization scope on every operational table, composite `(organization_id, id)` foreign keys, application-generated UUID v7 ids, `bigint` minor units with `currency`, `timestamptz`, revisions for sensitive edits, lifecycles from `packages/contracts/src/state-machines.ts`, database-enforced invariants, append-only tables with `forbid_mutation`, immutable migrations.

| Statement                                                                                                                                                                                                                                             | Status       | Evidence                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Core tables: facility references cannot cross organizations, audit records are append-only, open operational exceptions deduplicate by key, idempotency keys are unique per organization and scope, `btree_gist` exclusion constraints are available. | **Verified** | `packages/db/src/core-schema.spec.ts`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Applied migrations are immutable: the runner refuses to run when an applied migration changed on disk, rejects malformed names and duplicate versions, and rolls back a failing file as a unit.                                                       | **Verified** | `packages/db/src/migrate.spec.ts`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Each implemented module's own invariants are proved against the database, not only the service.                                                                                                                                                       | **Verified** | `modules/identity/__tests__/identity-schema.spec.ts`, `modules/catalog/__tests__/catalog-schema.spec.ts`, `modules/scheduling/__tests__/schema-invariants.spec.ts`, `modules/competition/__tests__/competition-schema.spec.ts`, `modules/competition/__tests__/matches-schema.spec.ts`, `modules/facilities/__tests__/schema-invariants.spec.ts`, `modules/communications/__tests__/schema-invariants.spec.ts`, `modules/enrollment/__tests__/enrollment-schema.spec.ts`, `modules/workforce/__tests__/workforce-schema.spec.ts` |
