# Architecture overview

Status legend: **Verified** = implemented and tested in this repository today (file cited). **Proposed** = engineering proposal from the specification or from this document, awaiting operator approval. **Pending decision** = needs an operator answer; the owner is named from specification §6.6. "No answer yet" never becomes "not applicable" (§6.6). Code that exists but that no test asserts is described as "implemented, not asserted by a test" and is never marked **Verified**.

Last derived from specification v2.0 (2026-10-22). Source: `docs/spec/master-specification.md` (repository copy supplied 2026-10-23). Repository state inspected 2026-10-30: `apps/api/src/modules/index.ts` lists 14 domain modules, all implemented (every module README describes its module as implemented and names the tests that verify it); `packages/db/migrations/` holds 120 migrations, `0001_core_schema.sql` to `1480_automation_org_scoped_kernel_fks.sql`.

This document describes the backend shape (§4.1), the kernel's request path and background work (§4.8 to §4.12, §4.14), how domain modules plug their authority into the kernel, and the module map (§4.2). Entities and lifecycles are in `docs/architecture/domain-model.md`; commands, errors and events are in `docs/architecture/api-and-events.md`. In the tables below, `kernel/` means `apps/api/src/kernel/` and `modules/` means `apps/api/src/modules/`.
