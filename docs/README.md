# Documentation index

Status legend: **Verified** = implemented and tested in this repository today (file cited); **Proposed** = engineering proposal from the specification or from a document here, awaiting operator approval; **Pending decision** = needs an operator answer (owner named from spec §6.6). "No answer yet" never becomes "not applicable" (§6.6).

Last derived from specification v2.0 (2026-10-22). Source: `docs/spec/master-specification.md` (repository copy supplied 2026-10-23). Repository tree last inspected for this index on 2026-10-30.

This index lists, with its path, every maintained documentation artifact that spec §6.7 requires (section 1), every Package A deliverable that spec §6.5 requires (section 2), and the supporting documents (section 3). Paths are relative to `docs/` unless they start with a repository directory. The status in each row summarises how that document labels its own content; the per-statement status, the document's own "Last derived" line and its own inspection date are in the document itself. Where a summary here and a document disagree, the document's per-statement status governs, and where a document's inspection statement and the code disagree, the code governs (the code is the only verified implementation).

## 6. Status discipline and maintenance (**Proposed**, consistent with §6.6 and §6.7)

1. Every document marks each statement **Verified**, **Proposed** or **Pending decision** (§6.7: "All documents must distinguish verified implementation, proposed behavior, and pending decisions").
2. **Verified** means implemented and tested in this repository today, with the file cited. A visible screen, a document or a template is not evidence that its workflow is complete (§1.5).
3. A **Pending decision** names its owner from the §6.6 table and its `DEC-###` record in `package-a/decision-register.md`. Each decision record keeps answer status (unknown, answered, not applicable) separate from proposal status (proposed, approved, rejected, superseded) (§6.6). "No answer yet" never becomes "not applicable" (§6.6).
4. A "proposed default" from the specification (for example the §4.15 two-hour maximum offline roster age) is reproduced as **Proposed** and stays so until its decision record is answered.
5. No document records a facility fact (field names, hours, prices, taxes, vendors, staff counts, competitor behaviour, performance numbers) that an operator has not supplied.
6. When a document is added to `docs/`, or a §6.7 artifact or §6.5 deliverable moves to another path, this index is updated in the same change.
