# @sportspark/api-client

Typed HTTP client for the Sportspark API, shared by the customer app (`apps/mobile`) and the staff
dashboard (`apps/staff`). Spec §4.1 ("Shared API and event contracts"), §4.8 to §4.10, §4.13.

Status legend (§6.7): **Verified** = implemented and asserted by a test in this package.
**Proposed** = engineering proposal awaiting operator approval. **Pending decision** = needs an
operator answer (owner from `docs/package-a/decision-register.md`).

## Using it

```ts
import { createApiClient, MemorySessionStore } from '@sportspark/api-client';

const api = createApiClient({
  baseUrl: 'http://localhost:3000/v1', // API origin plus the version prefix
  session: sessionStore, // SecureSessionStore (mobile), BrowserSessionStore (staff)
  clientInfo: { app: 'mobile', platform: 'ios', version: '0.1.0' },
  generateKey, // secure random keys; React Native passes expo-crypto's randomUUID
  onUpdateRequired: (e) => showUpdateRequired(e),
  onAuthenticationRequired: () => signOut(),
});

const page = await api.get('/me/inbox', { query: { limit: 50 } }); // typed InboxPage
const intent = api.newIntent(); // one per user decision; reuse it on retry
await api.post('/assignments/{id}/accept', {
  path: { id },
  body: { expectedRevision: assignment.revision },
  intent,
});
```

Screens do not call the client directly; they use the apps' `useApiQuery`, `useApiPages`,
`useApiCommand` and `usePermissions` hooks (see the app READMEs). Tests use
`@sportspark/api-client/testing`: `createFakeFetch` routes `"<METHOD> <template>"` to static or
computed responses and answers anything else `NOT_FOUND`, `fakeResponse`, `apiErrorBody`,
`sequentialKeys`, `fakePermissions(options)` (a `GET /v1/me/permissions` body: every area visible
and every capability off by default, `enabled: ['rentals']` to turn one on) and
`capabilityDisabledBody(capability, decisions)` (the ACCESS_DENIED `CAPABILITY_DISABLED` body).

## Gaps found in the API contract

- Closed in stage 3 (K-01, K-02): `@Idempotent()` is the single source of the `Idempotency-Key`
  header in the OpenAPI document, and `ErrorResponse.code` is a closed enum. The client still
  requires an intent on every non-GET call (harmless where a route is not idempotent) and keeps its
  own code list, tied to `packages/contracts` by a test.
- A turned-off capability has no error code of its own: it is ACCESS_DENIED with
  `details.code: 'CAPABILITY_DISABLED'` until DEC-092 decides otherwise (**Pending decision**,
  Technical lead/operator); `isCapabilityDisabled` reads exactly that shape.
